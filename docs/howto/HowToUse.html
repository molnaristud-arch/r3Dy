1Mit csinál a rendszer?

Egy tárgyat egy forgóasztalon körbefotózunk, a fotókból a laptop fotogrammetriával kiszámolja a tárgy textúrázott, valódi méretű 3D modelljét. A folyamatot egy AI ágens vezérli: minden lépés után dönt, a hibákat javítja, egy második ágens ellenőrzi a végeredményt, és a modell felkerül a weboldalra.

Felvételforgóasztal + telefon: 72 fotó vagy egy videó
→
BemásolásUSB-n a laptop data/bejovo/ mappájába
→
Feldolgozása vezérlő ágens futtatja és javítja: COLMAP, OpenMVS, Blender (10–20 perc)
→
Ellenőrzésminőségellenőrző ágens: ítélet, név, leírás, címkék
→
Weboldalforgatható 3D, AR, GLB/.blend letöltés

A modellt nem egy AI „találja ki”: a fotókból mérjük, ezért hű a valódi tárgyhoz. Hogy ez hogyan működik, a MUKODES.md írja le részletesen.

2Amire szükség van

Hardver

  • Laptop Linuxszal (Ubuntu 24.04+) vagy Windowson WSL2-vel, NVIDIA videokártyával (CUDA), 16 GB RAM ajánlott.
  • Android telefon az ingyenes Open Camera alkalmazással, USB-kábel.
  • Forgóasztal: tányér vagy forgótálca, vagy egy áram nélküli PC-ventilátor mint csapágy.
  • Nyomtatott korong (capture/disc_a4.svg), fehér háttér (karton), egyenletes fény.
  • Motoros forgóasztal: Arduino Nano, 28BYJ-48 (5 V) léptetőmotor ULN2003 panellel – 10°-onként lép és megáll, a fotót kézzel készítjük.
  • Telefontartó vagy állvány (akár könyvkupac): a telefon egy kör alatt nem mozdulhat.

Szoftver (a telepítés feltelepíti)

  • COLMAP 4.2 és OpenMVS 2.4 (CUDA) – a 3D számítás.
  • Blender – tisztítás, a korong levágása, méretezés a korongból, GLB-export.
  • Python-környezet (OpenCV, rembg) – videó, háttérkivágás.
  • Git – a feltöltés a weboldalra egy git push.
  • Opcionális: Arduino IDE a motorhoz.

Az ágensekhez Claude API-kulcs kell (console.anthropic.com), a repó gyökerében lévő .env fájlban: ANTHROPIC_API_KEY=sk-ant-…. A .env nincs a gitben – a kulcsot kézzel kell átadni.

3Első telepítés (egyszer)

Egy friss klónban minden benne van a futtatáshoz (kód, tesztképek), kivéve az API-kulcsot; a gépfüggő környezetet a setup.sh építi fel.

# 1. a repó letöltése
git clone git@github.com:molnaristud-arch/r3Dy.git
cd r3Dy

# 2. rendszercsomagok és a micromamba (egyszer)
sudo apt install -y ffmpeg blender python3-venv git curl
curl -sSfL https://micro.mamba.pm/api/micromamba/linux-64/latest | tar -xj -C ~/.local bin/micromamba

# 3. a környezet felépítése (első alkalommal néhány perc, utána ~30 s)
./setup.sh

# 4. Claude API-kulcs (a .env git-ignorált)
echo 'ANTHROPIC_API_KEY=sk-ant-…' > .env

Elvárt vége: COLMAP 4.2.1 … with CUDA, OpenMVS x64 v2.4.0, Blender …, onnxruntime ['TensorrtExecutionProvider', 'CUDAExecutionProvider'] és setup ok. Ha valami hiányzik, a szkript kiírja a telepítő parancsot.

Próbafutás a mellékelt tesztképekkel

mkdir -p data/teszt/images && cp data/sample/images/*.jpg data/teszt/images/
.venv/bin/python agent/controller.py data/teszt --size 0.3
[kész] KÉSZ (kb. 5 perc, 8 lépés)
rm -rf data/teszt
A tesztképek (egy kastélyhomlokzat) AGPL-licencűek: a belőlük készült modellt ne töltsd fel a weboldalra – ezért fut a próba --publish nélkül (az ágens amúgy is tiltja).

Windows: WSL2

  1. PowerShellben rendszergazdaként: wsl --install -d Ubuntu-24.04, majd újraindítás.
  2. Az Ubuntu-ablakban a fenti lépések. A Windows NVIDIA-illesztőprogramja a WSL-nek is adja a CUDA-t – a WSL-ben ne telepíts külön drivert.
  3. A repót a WSL saját fájlrendszerébe klónozd (~/), ne a /mnt/c alá.

4A forgóasztal és a tárgy előkészítése

  1. Korong: nyomtasd ki a capture/disc_a4.svg-t 100 %-os („tényleges”) méretben; a lap alján lévő skála vonalzóval mérve pontosan 5 cm legyen. Nagyobb tárgyhoz: disc_a3.svg.
  2. Alap: ragaszd a korongot a tányérra, forgótálcára vagy a ventilátorra. Az asztalra a korong mellé tegyél egy szalagot: ez a fix jel a forgatáshoz.
  3. Tárgy: matt és mintás, 10–25 cm-es (cipő, plüss, festett figura, kő, fa). Kerüld: üveg, fém, fényes műanyag, egyszínű fehér tárgy, vékony szálak. Tedd a szaggatott kör közepére. Lemérni nem kell: a méretet a program a 19 cm-es korongból számolja.
  4. Háttér: egyszínű (fehér karton vagy üres fal). Ez fontos: a háttér áll, a tárgy forog – egy mintás háttér összezavarja a programot.
  5. Fény: egyenletes, kemény árnyék nélkül (ablak felőli nappali fény vagy két lámpa két oldalról).

5A telefon beállítása (Android: Open Camera · iPhone: Kamera)

A telefont támaszd meg kb. 40–50 cm-re; a tárgy töltse ki a kép felét, a korong mintája is látsszon. Egy körön belül ne mozdítsd el, és ne váltogasd az álló/fekvő tájolást: a program a képek „fel” irányából állítja függőlegesbe a modellt.

6Felvétel: három lehetőség

Mindegyik esetben két kör kell: egy alacsonyról (kb. 20°-kal a tárgy fölül) és egy magasabbról (kb. 45°). A mi felállásunk a B): a motor forgat, mi exponálunk.

A) Kézi léptetés – ha nincs motor

Fotó → a tányért a következő 10°-os jelig forgatod → fotó … körönként 36 kép. Kb. 4 perc körönként.

B) Arduino léptetőmotor + kézi exponálás – a használt mód

Bekötés:

ULN2003 IN1–IN4 → D8–D11
ULN2003 + / -   → 5V / GND
gomb (opcionális) → D2 és GND

Feltöltés: Arduino IDE → capture/turntable_stepper/turntable_stepper.ino → Board: Uno/Nano → Upload. Serial Monitor: 115200 baud, „Newline”.

parancshatás
s / gomb36 megállás 10°-onként; minden megállásnál (FOTO k/36) egy fotó kézzel (~2 perc/kör)
cfolyamatos forgás (videóhoz), r1.0 = RPM
x / gombstop
n36 d4000 ?megállások · állásidő (ms; alap 2500, kényelmesebb 4000) · állapot

Exponálás: a tányér megáll → fél másodperc → egy finom érintés (vagy hangerőgomb). Egy kihagyott vagy dupla kép nem baj. Kör végén KESZ: emeld meg a telefont, és indítsd újra. A tárgy legyen 300 g alatt.

C) Videó – a leggyorsabb

Videó módban, zárolt fókusszal és expozícióval; a tányér lassan, folyamatosan forog: kb. 1 fordulat/perc (kézzel vagy a motor c parancsával). Egy videóban két kör: a kettő között emeld meg a telefont, a felvétel mehet tovább. Gyorsabb forgásnál a képek elmosódnak – egy 300 RPM-es ventilátor motornak ezért nem jó.

7Feldolgozás: a vezérlő ágens

Másold a fotókat (vagy a videót) USB-n – a telefonon „Fájlátvitel” mód, DCIM/OpenCamera – a data/bejovo/ mappába, majd indítsd az ágenst:

cd ~/r3Dy            # vagy ahová klónoztad
.venv/bin/python agent/controller.py --inbox

Az ágens a képeket egy új data/modell_N mappába teszi, majd lépésről lépésre végigmegy a láncon. Minden lépés után az eredményből dönt – hány kép illeszkedett, milyen hiba jött, hogy néz ki a modell –, és ha kell, javít:

[vezérlő]   Döntés: 72 fotó van, indulhat a rekonstrukció 2000 px-en.
[eszköz]    reconstruct({"max_image_size": 2000})
[eredmény]  reconstruct → {"ok": true, "total_images": 72, "registered_images": 51, …}
[vezérlő]   Döntés: csak 51/72 kép illeszkedett, a háttér zavarhat → háttérkivágás, újra.
[eszköz]    mask_background({})
…
[eszköz]    cleanup_model({"size_m": 0.2, "remove_disc": true})
[eredmény]  cleanup_model → {"disc_removed": true, "tilt_corrected_deg": 38.5, "object_size_cm": [6.2, 6.5, 1.0], …}
…
[eszköz]    quality_check({})
[eredmény]  quality_check → {"nev": "Fehér sportcipő", "minoseg": "jo", …}
[kész]      KÉSZ (12 perc 30 s, 11 lépés)

A korong levágása: a Blender-lépés (remove_disc) megkeresi a korong síkját, ahhoz vízszintezi a modellt, a korong ismert 19 cm-es átmérőjéből valódi méretre skáláz, majd levágja a korongot és ami alatta / körülötte van. Ezért kell, hogy a korong mintája a fotókon látsszon. 72 fotónál a futás kb. 8–20 perc; közben a laptop legyen töltőn.

kapcsolóhatás
--inboxa data/bejovo/ tartalmából új data/modell_N (helyette megadható egy meglévő mappa)
--size 0.24a tárgy leghosszabb mérete méterben – csak ha a korong nem használható (pl. nem látszik)
--publishengedélyezi a feltöltést a weboldalra (nélküle semmi nem kerül fel)
--max-steps 30legfeljebb ennyi eszközhívás
--model · --effortClaude-modell (alap: claude-opus-5-5) és gondolkodási szint (alap: high)
Napló: az ágens döntései a data/modell_N/agent_log.jsonl-ben, az eszközök teljes kimenete az agent_run.log-ban. Tartalék ágens nélkül (pl. nincs internet): ./pipeline/auto.sh --watch --size 0.24 --no-ai – ugyanaz a lánc, fix sorrendben.

8Minőségellenőrzés és feltöltés

A modell elkészülte után egy második, független ágens (minőségellenőrző) megnézi az előnézeti képeket és egy eredeti fotót, és JSON-ban ítél:

{"nev": "Fehér sportcipő",
 "leiras": "Fehér, bőr hatású sportcipő szürke talppal és fűzővel.",
 "cimkek": ["cipő", "ruházat"], "minoseg": "jo", "hibak": [], "javaslat": ""}

Minőség: jo – mehet; gyanus – felismerhető, de hibás részekkel (lyuk, foltos textúra, tapadt háttér, dől) – a vezérlő megpróbálja javítani; hibas – érdemes újrafotózni. A hiányzó vagy lapos alj és egy apró korongfolt a talp szélén normális.

Ha a futás --publish-sel indult, a vezérlő a jó modellt feltölti: a weboldal mappájába másolja, commitol, pushol, és megvárja, amíg a modell megjelenik a r3dy-web.vercel.app oldalon (~20 s). Ha nem, később ugyanarra a mappára:

.venv/bin/python agent/controller.py data/modell_1 --publish
Tartalék lánc: az auto.sh a végén ugyanettől az ágenstől kér javaslatot, és megkérdezi: Feltöltsem így? [I/n, s = szerkesztés] – Enter: feltöltés; n: nem; s: méret, név, címkék, leírás szerkesztése. Ha az AI nem érhető el, kézzel kérdez.

9A weboldal használata

https://r3dy-web.vercel.app – nyilvános, bárki megnyithatja; helyben: cd web && python3 -m http.server 8000.

  • Kártyák: minden modell forgatható (egér / ujj), nagyítható, magától lassan forog; alatta név, valódi méret, háromszögszám, leírás, címkék.
  • Keresés: név, leírás vagy címke szerint.
  • AR: telefonon a modellen megjelenő gombbal a tárgy valódi méretben a szobába helyezhető (Androidon és iPhone-on is).
  • Letöltés: „GLB letöltése” – bármely 3D programba, játékmotorba (Unity, Unreal, Godot) importálható; „.blend” – Blenderben szerkeszthető.
  • Blenderben: File → Import → glTF 2.0 – a modell méterben, valódi méretben, a talpa az origóban áll.

Ha frissítés után a régi oldal látszik: Ctrl+Shift+R.

10Kézi vezérlés (haladó)

Az ágens eszközei ezeket a lépéseket hívják – külön is futtathatók, pl. egy lépés megismétléséhez. Egy eszköz API nélkül: .venv/bin/python agent/tools.py data/cipo reconstruct '{"max_image_size": 1600}'.

# fotók: data/cipo/images/   (videóból: .venv/bin/python pipeline/extract_frames.py video.mp4 data/cipo/images --count 150)
.venv/bin/python pipeline/mask.py data/cipo/images data/cipo/masked      # opcionális háttérkivágás
./pipeline/reconstruct.sh data/cipo                                       # → data/cipo/model/model.obj
./blender/run.sh cleanup data/cipo/model/model.obj data/cipo/model.glb --remove-disc --blend   # korong le, méret a korongból
./blender/run.sh preview data/cipo/model.glb data/cipo/preview
.venv/bin/python agent/qa.py data/cipo                                    # minőségellenőrző ágens, JSON
.venv/bin/python pipeline/publish.py data/cipo/model.glb --name "Sportcipő" --tags cipő --description "…"
git add web/models && git commit -m "Add: sportcipő" && git push         # élesítés ~20 s

Levágás: eltűnt az alj → --cut-mm 0.5, korongmaradék → --cut-mm 2; más korong: --disc-diameter 0.25; korong nélkül: --size 0.28.

12Karbantartás

Modell levétele az oldalról

Töröld a bejegyzését a web/models/models.json-ból és a web/models/<név>.glb / .blend fájlt, majd git commit -am "Remove: <név>" && git push.

Az ágensek

  • API-kulcs: a .env-ben (ANTHROPIC_API_KEY); csere: új kulcs a console.anthropic.com-on, a régi visszavonása.
  • Viselkedés hangolása: a vezérlő döntési támpontjai az agent/controller.py SYSTEM_PROMPT-jában, a minőségellenőrző utasítása az agent/qa.py PROMPT-jában.
  • Költség: egy szkennelés jellemzően néhány tized dollár (a képek miatt).

13Gyors összefoglaló a demó napjára

  1. Laptop töltőn, böngésző zárva, ./setup.sh → setup ok.
  2. Forgóasztal: korong középen, fehér háttér, egyenletes fény, a tárgy lemérve.
  3. Telefon rögzítve, fókusz és expozíció zárolva, JPG, 2 s-os önkioldó.
  4. Két kör fotó (kézzel, s paranccsal vagy videóval) → bemásolás a data/bejovo/-ba.
  5. .venv/bin/python agent/controller.py --inbox --publish
  6. Amíg számol (10–20 perc): az ágens döntéseinek kommentálása, a korábbi modellek bemutatása, AR telefonon.
  7. [kész] KÉSZ → frissítés az oldalon: ott az új modell.
B terv: 2–3 előre beszkennelt modell legyen fent az oldalon. Ha az élő szkennelés elakad, azokkal is bemutatható minden, az agent_log.jsonl pedig megmutatja, hol tart a feldolgozás.
